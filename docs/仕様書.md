# ResinMixer 仕様書（レシピ出力用）

自作 UV レジンの配合計算・調合手順アプリ。レシピは JSON で受け取り、アプリはそれを表示・計算するだけ。
**このドキュメントの目的**: チャットでレシピを出力するときに、アプリがそのまま読める JSON を作ってもらうこと。

- 公開 URL: https://medama2008-glitch.github.io/resin-mixer/
- リポジトリ: https://github.com/medama2008-glitch/resin-mixer
- レシピ台帳: リポジトリ内 `public/recipes.json`（main に push すると数分で全端末に反映）
- 試したいだけなら、アプリの「インポート」画面に JSON を貼り付ければその端末だけで使える

---

## 1. アプリができること

| 画面 | 内容 |
|---|---|
| 一覧 | recipes.json のレシピをカード表示。active / experimental を表示し、archived は折りたたみ |
| 計算 | 目標バッチ量(g) を入れると全成分の必要量を表示。**基準成分の実測値を入れると他成分を `実測 ÷ ratio_base × ratio_i` で再計算** |
| 手順 | step 順に工程カードを表示（チェックボックス付き）。最後に印刷設定カード |
| インポート | JSON を貼り付けて端末内に保存。同じ id は recipes.json より優先され「ローカル」バッジが付く |

計算はすべて **質量比** で行う。ratio の合計は 100 でなくてもよい（比率として扱う）。
表示単位ははかりに合わせて切り替え可能（既定 0.1 g。0.01 g モードでは 10 g 未満のみ小数 2 桁）。
レシピ側の `ratio` は丸めずに書いてよい（丸めは表示時のみ）。

## 2. JSON スキーマ（schema_version: 1）

### 2.1 全体

```json
{
  "schema_version": 1,
  "recipes": [ { ...レシピ... }, { ...レシピ... } ]
}
```

インポート画面はこの全体形式のほか、**レシピオブジェクト単体** や **レシピの配列** も受け付ける。
recipes.json に書くときは必ず全体形式。

### 2.2 レシピオブジェクト

```json
{
  "id": "B-2",
  "status": "active",
  "date": "2026-09-01",
  "base_component": "L-6206",
  "components": [
    {"name": "L-6206",    "ratio": 61.0, "role": "oligomer",    "step": 3},
    {"name": "ACMO",      "ratio": 20.0, "role": "diluent",     "step": 1},
    {"name": "BAPO",      "ratio": 1.0,  "role": "initiator",   "step": 1, "note": "ACMO全量に溶解。30-40℃加温、完全透明まで撹拌"},
    {"name": "EO3-TMPTA", "ratio": 13.0, "role": "crosslinker", "step": 2},
    {"name": "L-6105",    "ratio": 4.7,  "role": "diluent",     "step": 2},
    {"name": "顔料(緑)",   "ratio": 0.3,  "role": "blocker",     "step": 2}
  ],
  "print_profile": {
    "exposure_s": 6.0,
    "bottom_layers": 3,
    "bottom_exposure_s": 40,
    "layer_mm": 0.05,
    "rest_after_retract_s": 2.0
  },
  "notes": "膜なし・BAPO完全溶解条件で0.6mm柱まで生存"
}
```

| フィールド | 必須 | 型 | 説明 |
|---|---|---|---|
| `id` | ○ | string | 一意。例 `B-2`, `B-3a`。同じ id を出すと上書き扱い |
| `status` | ○ | `"active"` / `"experimental"` / `"archived"` | 採用 / 試作 / 過去。古いレシピは削除せず archived にする |
| `date` | 任意 | string | `YYYY-MM-DD`。一覧はこの降順で並ぶ |
| `base_component` | ○ | string | 実測入力の基準となる成分名。**components 内の name と完全一致**すること。通常は最も注ぎにくい高粘度主剤 |
| `components` | ○ | 配列(1件以上) | 下記 |
| `print_profile` | 任意 | object | 値は数値か文字列。キーは自由だが下記 5 つは日本語ラベル付きで表示される |
| `notes` | 任意 | string | 一覧カードとレシピ画面の冒頭に表示 |

### 2.3 components の各行

| フィールド | 必須 | 型 | 説明 |
|---|---|---|---|
| `name` | ○ | string | レシピ内で一意。表示名としてそのまま使われる |
| `ratio` | ○ | number | 質量比 (wt%)。**文字列不可**（`"40"` はエラー）。0 以上 |
| `role` | ○ | string | `oligomer`(主剤) / `diluent`(希釈剤) / `crosslinker`(架橋剤) / `initiator`(開始剤) / `blocker`(ブロッカー)。他の文字列も通るがラベルはそのまま表示 |
| `step` | ○ | integer ≥ 1 | 作業工程のグループ番号（下記） |
| `note` | 任意 | string | その成分の注意書き。工程カードに黄色で表示 |

### 2.4 print_profile の既知キー

| キー | 表示 |
|---|---|
| `layer_mm` | 積層ピッチ (mm) |
| `exposure_s` | 露光時間 (s) |
| `bottom_layers` | 底面層数 (層) |
| `bottom_exposure_s` | 底面露光 (s) |
| `rest_after_retract_s` | リトラクト後待機 (s) |

未知のキーはキー名のまま表示される。

## 3. step と手順文言の生成ルール（重要）

手順カードの文言は **components / step / role / note から自動生成** される。文言を JSON に書く必要はない。
step 番号ごとに成分をまとめ、以下のルールで工程の種類が決まる。

| 種類 | 判定 | 生成される文言（例） |
|---|---|---|
| 先溶かし | **最小の step** に `initiator` と それ以外の成分が両方ある | `ACMO 21.7 g を容器に取り、BAPO 1.09 g を少量ずつ加えて溶解` |
| モノマーカクテル | 上記でも主剤合流でもない step | `EO3-TMPTA 14.1 g → L-6105 5.11 g → 顔料(緑) 0.33 g を追加して撹拌` |
| 主剤合流 | **`base_component` を含む step** | `L-6206 66.3 g（40-50℃加温済み）に Step 2 の液を全量注ぎ、ヘラで壁面をこそぎながら混合` |

補足:

- 同一 step 内の投入順は「開始剤以外 → 開始剤」。それ以外は JSON の記載順
- 主剤合流の step に base_component 以外の成分もある場合（複数オリゴマーのブレンド等）は
  `…混合。さらに L-9999 10.0 g を追加して撹拌` が続く
- 先溶かし〜カクテルの成分には「容器の累計 g」も表示される（風袋引きしない場合用）
- step 番号は 1, 2, 3 に限らない。4 以上も可。飛び番も可（表示は昇順）
- `note` は各成分に付け、工程カードの下にまとめて表示される

**典型的な割り当て**: step 1 = 低粘度液 + 光開始剤（先溶かし）、step 2 = 残りの低粘度成分、step 3 = 高粘度主剤（base_component）。

### 3.1 手順タブでの実際の並び（並行作業フロー）

先溶かし工程と主剤合流工程の両方があるレシピでは、アプリは上記の step をそのまま並べず、次の順に組み替えて表示する。
JSON 側で何かを書く必要はない。

1. **準備**: 主剤を「目安 × (1+余裕)」g 以上小分けして湯煎
2. **先溶かし（余裕 +5%）**: 湯煎の間に、計画量 × 1.05 で先溶かし液を作りスターラーにかける
3. **主剤計量**: 温まった主剤を計量して実測値を入力。許容範囲「目安 × (1−余裕) 〜 目安 × (1+余裕)」を表示（上限超えは先溶かし液が不足、下回るのは可）
4. **先溶かし液の調整**: 実測から求めた必要量との差を「はかりの風袋引き表示で −x.xx g になるまで抜く」と表示。実際に作った先溶かし液の量を入力すればそこから引く。不足時は主剤をいくら減らせばよいかを表示
5. **モノマーカクテル**: 実測基準で再計算した量
6. **主剤合流**

余裕率はアプリの手順タブで変更でき（既定 5%）、端末に記憶される。
先溶かし工程が無いレシピ（開始剤を最小 step に置かない等）は step 順のまま表示される。

## 4. バリデーション（インポート時 / 起動時にチェックされるもの）

エラーがあると位置付きで表示される（例: `recipes[0].components[2].ratio が数値ではありません`）。

- `schema_version` が 1 であること（全体形式のとき）
- `id` が空でない文字列、レシピ間で重複しない
- `status` が 3 種のいずれか
- `base_component` が components の `name` に存在する
- `components` が 1 件以上、`name` 重複なし、`ratio` が数値、`step` が 1 以上の整数
- `print_profile` の値が数値または文字列

## 5. チャットでレシピを出すときのお願い

1. **schema_version 1 の全体形式**（`{"schema_version":1,"recipes":[...]}`）で、コードブロックに JSON だけを出す
2. 新レシピは `experimental`、採用が決まったら `active`、置き換えられた旧レシピは `archived` に変更した行も一緒に出す
3. `base_component` は最も粘度が高く注ぎにくい成分にする
4. 数値はすべて数値型で（クォートしない）。コメントや末尾カンマは JSON として無効なので入れない
5. 手順の注意点は該当成分の `note` に書く（文言は自動生成されるので手順文そのものは不要）
6. 複数レシピをまとめて出してよい。recipes.json 全体を置き換える形でも、追加分だけでもどちらでも可

### 最小テンプレート

```json
{
  "schema_version": 1,
  "recipes": [
    {
      "id": "B-3",
      "status": "experimental",
      "date": "2026-09-02",
      "base_component": "L-6206",
      "components": [
        {"name": "L-6206", "ratio": 60.0, "role": "oligomer",    "step": 3},
        {"name": "ACMO",   "ratio": 22.0, "role": "diluent",     "step": 1},
        {"name": "BAPO",   "ratio": 1.0,  "role": "initiator",   "step": 1, "note": "ACMO に完全溶解させる"},
        {"name": "EO3-TMPTA", "ratio": 17.0, "role": "crosslinker", "step": 2}
      ],
      "print_profile": {"exposure_s": 6.0, "bottom_layers": 3, "bottom_exposure_s": 40, "layer_mm": 0.05},
      "notes": "B-2 から架橋剤を増量"
    }
  ]
}
```
